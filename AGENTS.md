# Repository Guide

## Overview

This is a static personal website and blog built with Astro, TypeScript, Tailwind CSS, and MDX. Use `pnpm`; `pnpm-lock.yaml` is the only dependency lockfile.

## Common Commands

- Install dependencies: `pnpm install`
- Start the development server: `pnpm dev`
- Check formatting: `pnpm format:check`
- Format the repository: `pnpm format`
- Lint: `pnpm lint`
- Build the production site and search index: `pnpm build`

Run formatting, linting, and the production build after substantive changes.

## Project Structure

- `src/pages`: Astro routes
- `src/layouts`: shared page layouts
- `src/components`: reusable Astro components
- `src/content`: blog posts and documentation
- `src/styles/global.css`: global styles, animations, and Tailwind configuration
- `src/scripts`: browser scripts compiled by `plugins/compile-scripts.js`
- `src/data`: site configuration and structured content
- `public`: static assets and compiled browser scripts
- `dist`: generated production output
- `podcast` and `scripts`: podcast artwork and media-generation utilities

## Working Conventions

- Follow the existing Astro and TypeScript patterns; prefer static Astro components over adding client-side JavaScript.
- Use the `@/` aliases defined in `tsconfig.json` for imports under `src` where an alias exists.
- Keep Tailwind utility classes consistent with nearby components and place reusable global behavior in `src/styles/global.css`.
- Preserve accessibility behavior, semantic HTML, keyboard navigation, dark mode, responsive layouts, and reduced-motion support.
- Keep blog and documentation content in their existing Markdown or MDX collections and preserve frontmatter schemas from `src/content.config.ts`.
- Do not hand-edit `public/scripts/*.js`; edit the corresponding file in `src/scripts` and let the build plugin compile it.
- Do not hand-edit `dist`; it is generated by `pnpm build` and is tracked for deployment.
- When changing dependencies, update both `package.json` and `pnpm-lock.yaml` with pnpm.
- Do not introduce a client framework or animation library for behavior that CSS, Astro, or a small browser script can provide.

## Formatting And Style

- Prettier is authoritative. The repository uses tabs, no semicolons, single quotes, and a 100-character print width.
- ESLint uses the Astro recommended rules and forbids `set:html` except in `src/components/BaseHead.astro`.
- Avoid formatting generated output directly. Format source files with `pnpm format`.
- Keep changes focused and do not rewrite unrelated content.

## Verification

- For content-only changes, run `pnpm format:check` and `pnpm build`.
- For code or configuration changes, run `pnpm format:check`, `pnpm lint`, and `pnpm build`.
- A successful build also regenerates the Pagefind search index and files under `dist`.
